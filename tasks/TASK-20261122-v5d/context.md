## Patterns to Follow
- Classic MV3 Non-ESM Script Compatibility: See `manifest.json` lines 21–36, `background.js` lines 322–339, `content.js` lines 211–227 — Keep all runtime scripts as vanilla ES2022+ classic scripts (zero build step, zero npm dependencies, no top-level ESM `import`/`export`), gating browser globals and CommonJS exports so `node --test` can require modules directly.
- Single-Writer Cloud Coordination & Serialized Queue: See `background.js` lines 3–10 & `pbi-docs/PBI-SANCTUM-ARCH-industry-grade-architecture.md` lines 112–114 — `background.js` coordinates Drive mutations via `enqueueOperation()` to avoid concurrent `PATCH`/cache races; coordinate `popup.js` sync/reconciliation with `background.js` (or LWW timestamp merge) so neither overwrites the other's changes.
- Safe Remote Read-Modify-Write Validation: See `background.js` lines 155–183 — Treat only empty (`!text.trim()`) or `404` responses as uninitialized `{ series: {} }`; abort before `PATCH` and set error badge on non-OK HTTP status, malformed JSON, or non-plain-object payloads.
- LWW Per-Series Reconciliation: See `docs/IMPLEMENTATION_PLAN.md` line 11 (Design Decision D1) — Resolve conflicts per manga series entry using `updated` ISO timestamps (Last-Write-Wins) when merging local cache and remote Drive data.
- Isolated-World SPA Navigation Detection: See `pbi-docs/PBI-SANCTUM-ARCH-industry-grade-architecture.md` lines 64 & 106–108 — Content scripts run in Chrome's isolated world where monkey-patching `history.pushState` misses page-world router calls; use `window.navigation` API (Chromium 102+) paired with `popstate` / `hashchange` fallbacks and URL change comparison (`lastUrl`), never observing `document` subtree mutations.
- Real-Function Unit Testing: See `test/background.test.js` & `test/content.test.js` — Import and test exported production functions directly with mocked `global.chrome`, `global.fetch`, `global.window`, `global.document`, and timer functions; drain background operations via `await enqueueOperation(async () => {})`.

## Anti-Patterns Flagged
- `content.js` lines 197–208: Uses `new MutationObserver(...)` with `observer.observe(document, { subtree: true, childList: true })`, firing on every DOM mutation during infinite webtoon scroll — must be removed in Phase 2 (note: `docs/IMPLEMENTATION_PLAN.md` D4/2.2 mentions `history.pushState` wrapping, whereas `pbi-docs/...` L64 & L106–108 and the Phase 2 task explicitly mandate `window.navigation` + `popstate`/`hashchange` due to isolated-world constraints).
- `content.js` lines 160–175: Fires `SYNC_CHAPTER` after a flat 3000ms timeout with no scroll-depth (>25%) engagement check, enabling quick accidental bounces/re-reads to sync.
- `content.js` line 71 (`kunmanga.com`): `getChapter()` still has a `"Reading"` fallback string when digits don't match (`isValidChapter` at line 87 blocks `"Reading"` from syncing, and monotonic numeric comparison must also handle non-numeric edge values safely).
- `background.js` lines 190–194 (`SYNC_CHAPTER`): Unconditionally overwrites `data.series[message.payload.manga]` with no monotonic chapter check (`numericNewChapter < numericSavedChapter`) and does not persist to `chrome.storage.local`.
- `background.js` lines 115–216 & 222–317: Drops mutations on offline/auth/Drive failures instead of enqueueing them under `pending_sync` in `chrome.storage.local`, and calls `findFile(token)` on every operation without checking a cached `fileId` (note: cached `fileId` logic must also recover if Drive returns `404` for a deleted/stale cached `fileId`).
- `popup.js` lines 200–255 (`loadVault`) & lines 152–175 (`deleteBtn` click): Performs blocking `getAuthToken({ interactive: true })` and two Drive `fetch` calls before rendering anything, lacks `chrome.storage.local` read/write integration, omits `&orderBy=createdTime` on its Drive search URL (line 210 vs `background.js` line 55), and executes top-level `document.getElementById` lookups (lines 1–14) without DOM guards.
- `test/preview/mock-chrome.js` lines 28–53 & `test/background.test.js` lines 227–709: Neither mocks `chrome.storage.local`; adding unguarded `chrome.storage.local` calls in `background.js` or `popup.js` without updating mocks/guards will break existing tests and the LAN preview harness (`test/preview/server.js`).

## MEMORY.md Notes
- **BUG-001 (API Integration — `background.js` Drive History Sync `SYNC_CHAPTER` & `DELETE_SERIES`):** Swallowing `JSON.parse` errors on non-empty Drive responses and falling back to `{ series: {} }` caused `PATCH` to overwrite remote reading history on corrupted HTTP 200 payloads. **Prevention:** In all remote read-modify-write handlers (including `pending_sync` reconciliation), never fall back to an empty object on `JSON.parse` errors or unexpected shapes (non-object/array); treat only empty (`!text.trim()`) or `404` responses as uninitialized and abort without calling `PATCH`, invoking `setErrorBadge()`.
- **BUG-002 (UI State — `background.js` Extension Action Badge State):** Untracked 3-second `setTimeout` in `setSuccessBadge()` allowed stale timers to clobber subsequent `"..."` or `"!"` states, and `DELETE_SERIES` success did not reset prior error badges. **Prevention:** Track every delayed UI/badge clear timer at module scope (`badgeClearTimer`) and call `clearBadgeTimer()` before every badge state transition (`setErrorBadge`, `setInFlightBadge`, `setSuccessBadge`); ensure new sync/reconciliation paths reuse these helpers instead of raw `chrome.action` calls.
- **BUG-003 (UI State — `popup.html` Box-Sizing & Viewport Dimensions):** Missing `box-sizing: border-box` and unwrapped `#filter-container` caused horizontal overflow and 30px left clipping in 350px/380px frames. **Prevention:** Always preserve `* { box-sizing: border-box; }`, `body { width: 380px; overflow-x: hidden; }`, and `flex-wrap: wrap;` on multi-item containers in `popup.html` when adding or adjusting status/sync UI elements.
- **LESSON-001 (Tooling / Harness — MV3 Classic Script Unit Testing):** MV3 classic scripts initially caused `test/content.test.js` to test a local `simulateCheck` clone instead of real `checkPage`. **Prevention:** Never replace production logic with local `simulate*` helpers in unit tests; export real functions via guarded CommonJS (`if (typeof module !== "undefined" && module.exports)`) with browser global/auto-init guards (`typeof window`, `typeof document`, `typeof chrome`, `typeof module === "undefined"`) so classic MV3 scripts run cleanly in both Chrome and `node --test`.
- **LESSON-002 (Tooling / Harness — Remote / Headless Extension Live Testing):** Extensions cannot run natively in standard remote browser tabs because `chrome.identity` and `chrome.runtime` are missing outside `chrome-extension://`. **Prevention:** Keep the in-repo dev harness (`test/preview/server.js`, `test/preview/index.html`, `test/preview/mock-chrome.js`) synchronized with all `window.chrome` APIs used by `popup.js` (including adding `chrome.storage.local` and any new `chrome.runtime.sendMessage` handlers) so LAN preview testing on port 3456 remains working.
