<Spec — Phase 2: Local-First Storage & SPA Navigation>
## Feature Summary
Implement Phase 2 ("Local-First Storage & High-Performance SPA Navigation") for the Sanctum Chrome Extension (Manifest V3) across `background.js`, `content.js`, `popup.js`, `popup.html`, and the `node:test` unit suite (`test/`). This task adds `chrome.storage.local` caching (`series`, `fileId`, `lastSync`) so the popup renders immediately on open, introduces a `pending_sync` offline mutation queue that reconciles `SYNC_CHAPTER` and `DELETE_SERIES` sequentially once online, eliminates the full-document `MutationObserver` in `content.js` in favor of targeted SPA navigation detection (`window.navigation` with `popstate`/`hashchange` fallbacks), adds a 15-second debounce combined with a >25% scroll-depth check before dispatching `SYNC_CHAPTER`, and enforces a monotonic chapter progress guard in `background.js`.

## Acceptance Criteria
1. **`chrome.storage.local` Caching (`background.js`, `popup.js`):** Persist the latest `series` map, Google Drive `fileId`, and `lastSync` ISO-8601 timestamp in `chrome.storage.local` (`<must match codebase convention — see context.md "Patterns to Follow">`) whenever cloud sync, vault initialization, `SYNC_CHAPTER`, or `DELETE_SERIES` updates state.
2. **Optimistic Local Cache Updates & `lastSync` Semantics (`background.js`, `popup.js`):** Local `SYNC_CHAPTER` (accepted by the monotonic guard) and `DELETE_SERIES` mutations immediately update the cached `series` map in `chrome.storage.local` regardless of online/offline status; `lastSync` is updated ONLY after a successful Google Drive sync (never faked while offline or failing).
3. **Immediate Popup Render (`popup.js`):** On popup open, `popup.js` reads cached state from `chrome.storage.local` and renders the cached `series` list immediately (sub-10ms perceived latency) before or in parallel with cloud synchronization, without blocking first paint on `chrome.identity.getAuthToken` or Google Drive `fetch`.
4. **Popup Cloud Refresh & Cache Preservation (`popup.js`):** After initial cached render, `popup.js` triggers background/cloud synchronization (including reconciling `pending_sync` when online) and updates the UI if cloud data changes. On empty cache (first run), it renders a clean loading/empty state; on offline, auth failure, or Drive error, it preserves and continues displaying cached `series` without clearing local storage.
5. **BUG-001 Malformed Drive JSON Protection (`background.js`, `popup.js`):** Preserve `MEMORY.md` BUG-001 invariant: an empty vault `{ series: {} }` is initialized only when the Drive response is `404` (on sync/creation) or `!text.trim()`. Any non-empty malformed JSON or non-plain-object/array Drive payload aborts before issuing `PATCH`, preserves cached `series` and `pending_sync`, and invokes `setErrorBadge()`.
6. **Popup CSS & Preview Harness Compatibility (`popup.html`, `test/preview/`):** Any status/sync UI additions in `popup.html`/`popup.js` preserve `MEMORY.md` BUG-003 layout rules (`* { box-sizing: border-box; }`, `body { width: 380px; overflow-x: hidden; }`, `#filter-container` `flex-wrap: wrap;`), and `test/preview/mock-chrome.js` (per LESSON-002) remains compatible with `chrome.storage.local` calls.
7. **Offline Mutation Queue (`pending_sync`) (`background.js`, `popup.js`):** When offline (`navigator.onLine === false`, where available) or when Google Drive requests fail (network error, transient auth failure, or non-2xx HTTP error other than `404` initialization), pending `SYNC_CHAPTER` and `DELETE_SERIES` mutations are appended in FIFO order to `chrome.storage.local` under key `pending_sync`, recording mutation `type`, payload (`<must match codebase convention — see context.md "Patterns to Follow">`), and `timestamp`.
8. **Monotonic Pre-Check Before Queuing (`background.js`):** A `SYNC_CHAPTER` mutation rejected by the monotonic chapter guard against the current cached local `series` entry (unless a preceding queued `DELETE_SERIES` removed that series) is NOT enqueued to `pending_sync` and does NOT overwrite the local cache.
9. **Sequential FIFO Reconciliation (`background.js`, `popup.js`):** On the next online sync (via `background.js` sync/mutation handlers or `popup.js` open/sync, and optionally `online` event if supported), if `pending_sync` is non-empty, fetch the current Drive vault (subject to BUG-001 validation), apply all queued mutations sequentially in FIFO order (enforcing the monotonic chapter guard on each `SYNC_CHAPTER` and removing entries on each `DELETE_SERIES`), write the merged vault once via `PATCH` (or `POST` on `404`), update `chrome.storage.local` (`series`, `fileId`, `lastSync`), and clear the reconciled items from `pending_sync`.
10. **Reconciliation Failure Retention & Concurrency Safety (`background.js`):** If Drive fetch or write fails (or Drive returns malformed JSON per BUG-001) during reconciliation, `pending_sync` remains intact for the next retry. Concurrent sync/reconciliation runs are serialized (or remove only the snapshotted reconciled prefix) so mutations enqueued while a Drive request is awaiting are not lost.
11. **Badge State Timer Hygiene (`background.js`):** Preserve `MEMORY.md` BUG-002 invariant: every action badge transition during online sync, offline queuing, reconciliation, and errors calls `clearBadgeTimer()` before updating state (`setInFlightBadge()`, `setSuccessBadge()`, `setErrorBadge()`), never leaving `"..."` stuck when queued offline.
12. **Remove Full-Document `MutationObserver` (`content.js`):** Completely remove any `MutationObserver` observing `document` (or `document.documentElement` / `document.body`) with `{ subtree: true, childList: true }` in `content.js`, yielding zero DOM-mutation observer overhead on infinite scroll.
13. **Targeted SPA Navigation Detection (`content.js`):** Implement SPA route detection using `window.navigation` (Chromium 102+ — e.g., `navigatesuccess` / `currententrychange` when available) with `popstate` and `hashchange` fallback listeners on `window`, deduplicated by current URL (`location.href`).
14. **SPA Route-Change State Reset (`content.js`):** When SPA navigation changes the active URL, cancel any active 15-second sync debounce timer from the previous route, reset per-route scroll-depth/sync state, and re-run page detection (`checkPage` / `<must match codebase convention — see context.md "Patterns to Follow">`).
15. **15-Second Debounce + >25% Scroll-Depth Gate (`content.js`):** `content.js` must NOT dispatch `SYNC_CHAPTER` until both conditions hold for the active chapter route:
    - At least 15 seconds (15,000 ms) have elapsed since chapter detection on the current route (cancelled/restarted on route change, NOT reset on individual scroll events).
    - Scroll depth is strictly `> 25%` (`scrollableHeight = scrollHeight - viewportHeight`; if `scrollableHeight <= 0`, scroll depth evaluates as satisfied/`1.0` so non-scrollable single-viewport chapters still sync after 15s; otherwise `scrollTop / scrollableHeight > 0.25`).
16. **Scroll/Dwell Convergence & Single Dispatch (`content.js`):** If 15s elapses while scroll depth is `<= 25%`, `SYNC_CHAPTER` is withheld until the user scrolls `> 25%` on that route; if the user scrolls `> 25%` early and leaves before 15s, `SYNC_CHAPTER` is not dispatched; once dispatched for the current chapter/URL, subsequent scroll events on the same URL do not dispatch duplicate `SYNC_CHAPTER` messages.
17. **Passive Listeners & Node Test Guards (`content.js`):** Register scroll listeners with `{ passive: true }` (when options supported) and guard all browser globals (`window`, `document`, `chrome`, `window.navigation`) and auto-initialization (`typeof module === "undefined"`, per `MEMORY.md` LESSON-001) so `content.js` loads cleanly under Node.js.
18. **Monotonic Chapter Guard (`background.js`):** In `SYNC_CHAPTER` (and queued `SYNC_CHAPTER` reconciliation), reject progress overwrites whenever `numericNewChapter < numericSavedChapter` (e.g., re-reading Chapter `1` must not downgrade saved Chapter `100`).
19. **Robust Chapter Parsing & Timestamp Fallback (`background.js`):** Preserve robust parsing for integer (`"100"`), decimal (`"150.5"`), and fractional/hyphenated (`"12-1"`) chapter identifiers (`<must match codebase convention — see context.md "Patterns to Follow">`). When either incoming or saved chapter is non-numeric (e.g., `"Prologue"`, `"Extra"`, `""`, `null`), fall back to timestamp ordering (only update when incoming timestamp is newer than or equal to saved timestamp).
20. **Non-Error Monotonic Rejection Behavior (`background.js`):** When `SYNC_CHAPTER` is rejected by the monotonic chapter guard or timestamp fallback, do not modify `chrome.storage.local`, do not call Drive `PATCH`, do not enqueue to `pending_sync`, do not trigger `setErrorBadge()`, and return a clean non-error response (`<must match codebase convention — see context.md "Patterns to Follow">`).
21. **Automated `node:test` Unit Tests (`test/`):** Export real functions via `if (typeof module !== "undefined" && module.exports)` with browser global guards (per `MEMORY.md` LESSON-001) and expand `test/background.test.js` and `test/content.test.js` with `node:test` coverage for `chrome.storage.local` caching, BUG-001 preservation, `pending_sync` enqueuing & sequential reconciliation (including partial failure/re-entrancy), monotonic chapter comparison (integer, decimal, fractional, equal, non-numeric timestamp fallback), scroll-depth gating (`<=25%`, `>25%`, non-scrollable edge case), 15-second debounce + route cancellation, SPA navigation listeners, and absence of `document` `MutationObserver`.

## Out of Scope
- OAuth flow redesign, multi-account sync, or custom remote server backends outside Google Drive.
- Migration to `chrome.storage.sync` (explicitly scoped to `chrome.storage.local`).
- Manual user chapter downgrade/override UI in `popup.html` (unless already present in codebase).
- Future architecture phases from `PBI-SANCTUM-ARCH-industry-grade-architecture.md` outside Phase 2.
- Major refactoring of `test/preview/` beyond keeping `chrome.storage.local` shimmed/compatible for popup preview and verification.

## Fallback Behaviors
- **Offline / Drive unreachable on popup open:** `popup.js` immediately renders cached `series` from `chrome.storage.local` and retains cached data on cloud sync failure, displaying non-destructive offline/status feedback without throwing or wiping state.
- **Offline / Drive failure during `SYNC_CHAPTER` or `DELETE_SERIES`:** Mutation updates local `series` cache (respecting monotonic guard for `SYNC_CHAPTER`), appends to `pending_sync` in `chrome.storage.local`, preserves `lastSync` unchanged, and clears any in-flight badge indicator via `clearBadgeTimer()`.
- **Malformed non-empty Drive JSON (BUG-001):** Abort before `PATCH`, keep `chrome.storage.local` `series` and `pending_sync` intact, and call `setErrorBadge()`.
- **Environment missing `window.navigation`:** `content.js` automatically falls back to `window` `popstate` and `hashchange` listeners without error.
- **Environment missing `chrome.storage.local` (e.g., partial preview mock):** `popup.js` checks capability / ensures `test/preview/mock-chrome.js` provides `chrome.storage.local` shim so popup opens without uncaught errors.

## Resolved Ambiguities
- **Scroll-depth edge case on short vs tall pages:** Resolved via `scrollableHeight = scrollHeight - viewportHeight`; when `scrollableHeight <= 0` (single-screen chapter), depth evaluates as `1.0` (`> 0.25`) so 15s dwell still syncs, while scrollable pages use `scrollTop / scrollableHeight > 0.25` so un-scrolled (`scrollY = 0`) quick tab previews never satisfy the gate.
- **15-second debounce on continuous scrolling:** Resolved as a per-route 15s chapter debounce/dwell timer (cancelled on SPA URL change, NOT reset on individual scroll events), gated by `> 25%` scroll depth so continuous readers still sync once both conditions hold.
- **MV3 isolated world SPA routing:** Resolved via `window.navigation` (fires across Chromium isolated worlds on `pushState`/`replaceState`) plus `popstate` / `hashchange` fallbacks rather than page-world `history` monkeypatching.
- **`lastSync` vs optimistic local cache:** Resolved so local `series` reflects queued local changes immediately across popup opens, while `lastSync` updates strictly on successful Google Drive sync.
- **Malformed Drive JSON vs offline queueing:** Resolved via `MEMORY.md` BUG-001: malformed Drive JSON aborts write without clearing `pending_sync` or overwriting cached `series`.
- **Badge timer race conditions:** Resolved via `MEMORY.md` BUG-002: all badge transitions invoke `clearBadgeTimer()` first.
- **Popup CSS & CommonJS test exports:** Resolved via `MEMORY.md` BUG-003, LESSON-001, and LESSON-002.
