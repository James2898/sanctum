## Feature Summary

Implement Phase 2 ("Local-First Storage & High-Performance SPA Navigation") for the Sanctum Chrome Extension (Manifest V3) across `background.js`, `content.js`, `popup.js`, `popup.html`, and the `node:test` unit suite (`test/`). This task adds `chrome.storage.local` caching (`series`, `fileId`, `lastSync`) so the popup renders immediately on open, introduces a `pending_sync` offline mutation queue that reconciles `SYNC_CHAPTER` and `DELETE_SERIES` sequentially once online, eliminates the full-document `MutationObserver` in `content.js` in favor of targeted SPA navigation detection (`window.navigation` with `popstate`/`hashchange` fallbacks), adds a 15-second debounce combined with a >25% scroll-depth check before dispatching `SYNC_CHAPTER`, and enforces a monotonic chapter progress guard in `background.js`.

- [x] **1. `chrome.storage.local` Caching (`background.js`, `popup.js`):** Persist the latest `series` map, Google Drive `fileId`, and `lastSync` ISO-8601 timestamp in `chrome.storage.local` (`<must match codebase convention — see context.md "Patterns to Follow">`) whenever cloud sync, vault initialization, `SYNC_CHAPTER`, or `DELETE_SERIES` updates state.

Offline Mutation Queue (`pending_sync`) (`background.js`, `popup.js`):** When offline (`navigator.onLine === false`, where available) or when Google Drive requests fail (network error, transient auth failure, or non-2xx HTTP error other than `404` initialization), pending `SYNC_CHAPTER` and `DELETE_SERIES` mutations are appended in FIFO order to `chrome.storage.local` under key `pending_sync`, recording mutation `type`, payload (`<must match codebase convention — see context.md "Patterns to Follow">`), and `timestamp`.
- [x] **8. Monotonic Pre-Check Before Queuing (`background.js`):** A `SYNC_CHAPTER` mutation rejected by the monotonic chapter guard against the current cached local `series` entry (unless a preceding queued `DELETE_SERIES` removed that series) is NOT enqueued to `pending_sync` and does NOT overwrite the local cache.
- [x] **9. Sequential FIFO Reconciliation (`background.js`, `popup.js`):** On the next online sync (via `background.js` sync/mutation handlers or `popup.js` open/sync, and optionally `online` event if supported), if `pending_sync` is non-empty, fetch the current Drive vault (subject to BUG-001 validation), apply all queued mutations sequentially in FIFO order (enforcing the monotonic chapter guard on each `SYNC_CHAPTER` and removing entries on each `DELETE_SERIES`), write the merged vault once via `PATCH` (or `POST` on `404`), update `chrome.storage.local` (`series`, `fileId`, `lastSync`), and clear the reconciled items from `pending_sync`.
- [x] **10. Reconciliation Failure Retention & Concurrency Safety (`background.js`):** If Drive fetch or write fails (or Drive returns malformed JSON per BUG-001) during reconciliation, `pending_sync` remains intact for the next retry. Concurrent sync/reconciliation runs are serialized (or remove only the snapshotted reconciled prefix) so mutations enqueued while a Drive request is awaiting are not lost.
- [x] **11. Badge State Timer Hygiene (`background.js`):** Preserve `MEMORY.md` BUG-002 invariant: every action badge transition during online sync, offline queuing, reconciliation, and errors calls `clearBadgeTimer()` before updating state (`setInFlightBadge()`, `setSuccessBadge()`, `setErrorBadge()`), never leaving `"..."` stuck when queued offline.

- [x] **13. Targeted SPA Navigation Detection (`content.js`):** Implement SPA route detection using `window.navigation` (Chromium 102+ — e.g., `navigatesuccess` / `currententrychange` when available) with `popstate` and `hashchange` fallback listeners on `window`, deduplicated by current URL (`location.href`).

- [x] **15. 15-Second Debounce + >25% Scroll-Depth Gate (`content.js`):** `content.js` must NOT dispatch `SYNC_CHAPTER` until both conditions hold for the active chapter route:

### Architecture & Implementation Details

1. **`chrome.storage.local` Schema:**
   - `series`: Object mapping series identifier -> series reading progress object (matching existing Drive vault `series` map and `updated` ISO timestamp convention).
   - `fileId`: String Google Drive vault file ID cached to avoid redundant `findFile(token)` calls on every sync (must recover via `findFile`/`createFile` if Drive returns `404` on stale `fileId`).
   - `lastSync`: ISO-8601 timestamp string updated **only** after a successful Google Drive read/write sync (never faked while offline or failing).
   - `pending_sync`: Array of queued mutation records in FIFO order, recording `type` (`"SYNC_CHAPTER"` | `"DELETE_SERIES"`), `payload`, and `timestamp`.
2. **Local-First Cache Rendering in `popup.js`:**
   - On open, read `chrome.storage.local` first and render cached `series` immediately (sub-10ms perceived latency) before or in parallel with cloud synchronization.
   - Never block first paint on `chrome.identity.getAuthToken({ interactive: true })` or Drive `fetch`.
   - On empty cache, show clean loading/empty state; on offline/auth/Drive failure, preserve cached `series` and display non-destructive status feedback.
3. **Offline Mutation Queue (`pending_sync`) & Sequential FIFO Reconciliation (`background.js`):**
   - Coordinate all `chrome.storage.local` updates, Drive mutations, and `pending_sync` reconciliation sequentially via `enqueueOperation()` (`background.js` lines 3–10) to eliminate concurrent write/PATCH races.
   - Reuse and consolidate the Drive fetch + `JSON.parse` validation logic (`background.js` lines 146–187 & 253–294) into a single shared helper used by `SYNC_CHAPTER`, `DELETE_SERIES`, and `pending_sync` reconciliation.
   - On online sync/reconciliation, fetch remote vault, validate per BUG-001, replay `pending_sync` FIFO (enforcing monotonic guard on `SYNC_CHAPTER` and deletions on `DELETE_SERIES`, plus LWW `updated` timestamp merge where applicable), write once via `PATCH` (or `POST` on `404`), update `series`/`fileId`/`lastSync`, and remove only the reconciled snapshotted prefix from `pending_sync`.
4. **Monotonic Chapter Guard (`background.js`):**
   - Reject `SYNC_CHAPTER` (both live and queued) when `numericNewChapter < numericSavedChapter`.
   - Support integer (`"100"`), decimal (`"150.5"`), and fractional/hyphenated (`"12-1"`) chapter formats consistently.
   - When either chapter is non-numeric (`"Prologue"`, `"Extra"`, `""`, `null`), fall back to timestamp comparison (allow update only when incoming timestamp >= saved timestamp).
   - On rejection: leave `chrome.storage.local`, Drive, `pending_sync`, and action badge untouched, and return a clean non-error response.
5. **High-Performance SPA Navigation & Scroll/Debounce Gate (`content.js`):**
   - Remove `new MutationObserver(...)` observing `document` with `{ subtree: true, childList: true }` (`content.js` lines 197–208).
   - Detect SPA navigation using `window.navigation` (`navigatesuccess` / `currententrychange`, or `navigate` checking destination URL) with `popstate` and `hashchange` fallbacks on `window`, deduplicated by `location.href` (`lastUrl`). Do NOT monkeypatch `history.pushState` (isolated-world limitation).
   - On URL change: cancel active timers (`clearAllTimers()`), reset per-route scroll-depth & dispatched flags, and re-run `checkPage`.
   - Gate `SYNC_CHAPTER` behind **both**: (a) 15,000 ms elapsed since chapter detection on the current route (cancelled on route change, NOT reset by individual scroll events), and (b) scroll depth `> 25%` (`scrollableHeight = scrollHeight - viewportHeight`; if `scrollableHeight <= 0`, treat depth as `1.0` so single-viewport chapters still sync; otherwise `scrollTop / scrollableHeight > 0.25`). Dispatch at most once per chapter/URL.
   - Register scroll listeners with `{ passive: true }` and guard browser globals + auto-init (`typeof module === "undefined"`).
6. **Test Plan:**
   - Run `node --test test/*.test.js` after expanding `test/background.test.js` and `test/content.test.js` (and adding any popup helper tests if applicable).
   - Verify `test/preview/mock-chrome.js` stubs `chrome.storage.local` and any new runtime messages for LAN preview testing.

### Fallback Behaviors

- **Offline / Drive unreachable on popup open:** `popup.js` immediately renders cached `series` from `chrome.storage.local` and retains cached data on cloud sync failure, displaying non-destructive offline/status feedback without throwing or wiping state.
- **Offline / Drive failure during `SYNC_CHAPTER` or `DELETE_SERIES`:** Mutation updates local `series` cache (respecting monotonic guard for `SYNC_CHAPTER`), appends to `pending_sync` in `chrome.storage.local`, preserves `lastSync` unchanged, and clears any in-flight badge indicator via `clearBadgeTimer()`.
- **Malformed non-empty Drive JSON (BUG-001):** Abort before `PATCH`, keep `chrome.storage.local` `series` and `pending_sync` intact, and call `setErrorBadge()`.
- **Environment missing `window.navigation`:** `content.js` automatically falls back to `window` `popstate` and `hashchange` listeners without error.
- **Environment missing `chrome.storage.local` (e.g., partial preview mock):** `popup.js` checks capability / ensures `test/preview/mock-chrome.js` provides `chrome.storage.local` shim so popup opens without uncaught errors.

### MEMORY.md Prevention Rules (inlined — do not re-read MEMORY.md)

> _Copied verbatim from `context.md` → MEMORY.md Notes. This is the canonical list of past-bug prevention rules for `@fullstack-developer`, `@release-manager`, and `@validator-agent`. They MUST NOT re-read `MEMORY.md` directly; trust this list._

- **BUG-001 (API Integration — `background.js` Drive History Sync `SYNC_CHAPTER` & `DELETE_SERIES`):** Swallowing `JSON.parse` errors on non-empty Drive responses and falling back to `{ series: {} }` caused `PATCH` to overwrite remote reading history on corrupted HTTP 200 payloads. **Prevention:** In all remote read-modify-write handlers (including `pending_sync` reconciliation), never fall back to an empty object on `JSON.parse` errors or unexpected shapes (non-object/array); treat only empty (`!text.trim()`) or `404` responses as uninitialized and abort without calling `PATCH`, invoking `setErrorBadge()`.
- **BUG-002 (UI State — `background.js` Extension Action Badge State):** Untracked 3-second `setTimeout` in `setSuccessBadge()` allowed stale timers to clobber subsequent `"..."` or `"!"` states, and `DELETE_SERIES` success did not reset prior error badges. **Prevention:** Track every delayed UI/badge clear timer at module scope (`badgeClearTimer`) and call `clearBadgeTimer()` before every badge state transition (`setErrorBadge`, `setInFlightBadge`, `setSuccessBadge`); ensure new sync/reconciliation paths reuse these helpers instead of raw `chrome.action` calls.
- **BUG-003 (UI State — `popup.html` Box-Sizing & Viewport Dimensions):** Missing `box-sizing: border-box` and unwrapped `#filter-container` caused horizontal overflow and 30px left clipping in 350px/380px frames. **Prevention:** Always preserve `* { box-sizing: border-box; }`, `body { width: 380px; overflow-x: hidden; }`, and `flex-wrap: wrap;` on multi-item containers in `popup.html` when adding or adjusting status/sync UI elements.
- **LESSON-001 (Tooling / Harness — MV3 Classic Script Unit Testing):** MV3 classic scripts initially caused `test/content.test.js` to test a local `simulateCheck` clone instead of real `checkPage`. **Prevention:** Never replace production logic with local `simulate*` helpers in unit tests; export real functions via guarded CommonJS (`if (typeof module !== "undefined" && module.exports)`) with browser global/auto-init guards (`typeof window`, `typeof document`, `typeof chrome`, `typeof module === "undefined"`) so classic MV3 scripts run cleanly in both Chrome and `node --test`.
- **LESSON-002 (Tooling / Harness — Remote / Headless Extension Live Testing):** Extensions cannot run natively in standard remote browser tabs because `chrome.identity` and `chrome.runtime` are missing outside `chrome-extension://`. **Prevention:** Keep the in-repo dev harness (`test/preview/server.js`, `test/preview/index.html`, `test/preview/mock-chrome.js`) synchronized with all `window.chrome` APIs used by `popup.js` (including adding `chrome.storage.local` and any new `chrome.runtime.sendMessage` handlers) so LAN preview testing on port 3456 remains working.
